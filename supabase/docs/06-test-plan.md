# 06 — خطة الاختبار

> تُنفَّذ في **بيئة تطوير مؤقتة** (مشروع Supabase تجريبي) قبل أي استخدام حقيقي.

## 0) التحضير

- أنشئ مشروع Supabase تجريبيًا (سم "staging").
- نفّذ الملفات `0001` → `0011` بالترتيب، ثم `seed/seed_questions.sql`.
- انشر دالتي الرفع:
  `supabase functions deploy upload-request --verify-jwt true` ثم
  `supabase functions deploy upload-confirm --verify-jwt true`.
- أنشئ مستخدم مالك + admin عبر خطوات `docs/04`.
- سجّل رابط/anon key ورابط المشروع في `config.js`.
- تحقق أن قيمة `SUPABASE_ANON_KEY` في بيئة دالة Edge تطابق المفتاح الذي ترسله
  الواجهة فعلًا (وإلا عدّل فحص المطابقة في الدالتين، أو فعّل `verify_jwt`).

## 5) الرفع (تدفق Edge Function — القرار المعتمد، انظر 03/05)

| # | الفحص | المتوقع |
|---|-------|---------|
| 5.1 | `rpc('register_upload', ...)` من الواجهة (anon) | رفض (لا EXECUTE) |
| 5.2 | `rpc('confirm_upload', ...)` من الواجهة (anon) | رفض (لا EXECUTE) |
| 5.3 | `POST /upload-request` بلا anon key | 401 |
| 5.4 | `POST /upload-request` بسؤال غير file/image | 400 (register_failed) |
| 5.5 | `POST /upload-request` بحجم >10MB أو صفر | 400 |
| 5.6 | `POST /upload-request` باسم ملف >255 حرفًا أو `../../x` | تُنقّى/يُرفض، ولا خروج عن `pending/<token>/` |
| 5.7 | رفع مباشر من anon لأي مسار Storage | رفض (لا سياسة INSERT) |
| 5.8 | `PUT signedUrl` ثم `POST /upload-confirm` | `ok:true` ثم `status='uploaded'` |
| 5.9 | `POST /upload-confirm` بلا رفع فعلي (لا كائن) | 409 (object_missing) |
| 5.10 | رفع بحجم فعلي ≠ المُعلَن (أو >10MB) في confirm | 409 (invalid_actual_size) |
| 5.11 | رفع بنوع فعلي خارج القائمة (مثلاً `.exe` برأس صورة) | 409 (mime_not_allowed) |
| 5.12 | إحضار token ثم `submit_response` | ينجح الإرفاق (attached) |
| 5.13 | `submit_response` بحجز `pending` غير مؤكَّد | رفض `E_UPLOAD: not confirmed` |
| 5.14 | إعادة استخدام token بعد الإرفاق | رفض `E_UPLOAD` |
| 5.15 | token منتهي (`expires_at`) في confirm وفي submit | رفض في كلتا المرحلتين |
| 5.16 | token من سؤال آخر | رفض |
| 5.17 | token من جلسة/زائر آخر | لا يمنح وصولًا إلا لحامله (capability)؛ لا يقرأ بياناته |
| 5.18 | إعادة استدعاء confirm بعد `attached` | 409 |
| 5.19 | تجاوز `RATE_LIMIT_PER_MINUTE` | 429 بعد الحد |
| 5.20 | تنزيل ملف من دون JWT مسؤول | رفض |

| # | الفحص | المتوقع |
